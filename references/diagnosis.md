# 从目标差距诊断损失与改进机制

**简体中文** | [English](en/diagnosis.md)

诊断要帮助选择能够改善当前目标的机制。它既处理错误，也处理**程序合法、计划照常执行，但解质量不足**的情况。已有证据就进入决策，不机械地把整套流程再走一遍。

## 1. 先接手当前方案与成绩

第一步读取当前求解入口和关键实现，确认实际启用的搜索、列车排序、多车协调、改进搜索和故障恢复；同时读取已有结果与评分材料。先判断“现在能做什么、主要缺什么”，不要从通用算法课或让用户重述代码开始。只看算法名称不够：一个标为 LNS 的空壳和具有有效联合邻域的实现不是同一起点。

用户没有另定优化目标时，默认朝当前 benchmark 的 **100% / 满分** 推进，不再询问要不要满分。先从规则确认满分对应的指标、计分公式和硬约束；全部到达不自动等于满分，未知公式不自行换算。若该 benchmark 没有定义满分，保留争取最好可达成绩的方向，并补问评价口径，不能伪造百分比。明确限定的修复或学习请求仍遵循其范围。

从材料取得最新成绩、最好已验证成绩及对应版本、逐项/逐例评分、benchmark 与评测条件。缺什么就问什么；例如缺少成绩与规则时，直接问：“请提供当前版本与历史最好版本的实际得分及对应版本、逐项或逐例评分，以及 benchmark 的评分规则和运行限制。”已有的信息不重复问。等待回复时继续源码审查、定位评测入口与可恢复基线；不编造分数，也不把缺少评分依据当成先跑大批实验的理由。

区分官方/服务器指标、官方本地结果和自定义代理。先交代一句接手判断：当前算法骨架与完成度、有效成绩、主要差距及下一步改动幅度；成绩尚缺时标明判断暂定。主指标未知时不能用等待数、总代价等自行替代。

用已有逐例结果整理简短的差距表：

| 损失或未解部分 | 与主目标的关系 | 当前证据 | 候选解释或下一项观测 |
| --- | --- | --- | --- |
| 使用者工程中观察到的失败、质量缺口或资源瓶颈 | 已核实的计分影响；无法量化则注明 | 版本、实例/片段、指标或相关函数 | 能改变决策的机制解释及如何区分 |

未完成、晚到、等待可能重叠，不直接相加。若已知评价公式可做可靠分解，就按该公式排序主要损失；公式不明时按实际返回的主指标及可追溯案例调查，不能制造精确的收益预测。

只有规则或有依据的界能证明的部分，才称为不可避免的损失。单车松弛问题的下界可以显示某类改进空间，但未必能分解多车相互影响或证明整局最优。其余保持“尚未解释”；当前没有改善不等于理论极限。

先处理影响硬约束且已定位的错误，再根据目标损失、证据、机制潜力及实施/验证成本选择方向。最容易修的小问题不一定是最值得推进的质量缺口。

## 2. 把目标与当前源码接起来

只读取相关调用链，记录当前使用者的文件/函数：

| 关系 | 从哪里取得证据 |
| --- | --- |
| 哪些决策影响主指标 | 评测器、候选选择判据、代价与惩罚计算。检查代理目标是否真对应最终评价。 |
| 初始计划怎样形成 | 路径搜索、任务/列车顺序、约束表示及失败返回；区分无解、未找到和预算截断。 |
| 后续搜索改变了什么 | 邻域生成、受影响列车选择、接受/最好解逻辑、实际访问与退出记录。 |
| 计划怎样变成动作与占用 | 计划消费者、动作转换、速度/区间、tick 前后阶段及到达后的状态语义。 |
| 事件发生后怎样协调 | 故障处理、依赖关系、共享约束、局部修复和计划交接。 |
| 有限计算花在哪里 | 剖析或相关计时，区分有效搜索、重复维护、仿真、日志及框架开销。 |

工具不能从轨迹猜出修改函数，也不能证明某算法模块在用户工程中必需。根据实际代码核实职责，再选择改动幅度：

| 接手后的判断 | 起步方式 |
| --- | --- |
| 单车最短路拼接、固定顺序规划等简单骨架，且评分损失反映其协调能力不足 | 保留可运行基线，直接构建能表达缺失决策的强候选，例如适合当前约束的时空搜索、优先级多样性与相关列车联合重规划。需要协同工作的模块可一起实现，不先逐项打磨注定受限的弱骨架。 |
| 已有较完整规划与修复，但某类损失明显 | 复用有效模块，围绕瓶颈改变排序、联合邻域、路线/时序选择或恢复机制；不用重新从简单算法开始。 |
| 高分且功能成熟，剩余损失小而集中 | 从逐例差距及实际搜索行为选择精细机制、参数组合或预算分配试验；高分不等于已经最优。 |

这是代码、成绩和细则共同支持的决策，不是按分数阈值安装固定算法套餐。简单骨架若已满足该任务就不为复杂而复杂；有明显能力缺口时，也不要求先证明每个微调都失败才升级。

## 3. 根据证据区分错误与质量瓶颈

| 当前证据 | 先核实什么 | 可调查的机制方向 |
| --- | --- | --- |
| 同一时刻计划与实际不一致 | 时钟、计划版本、动作和状态转换；向前追到能解释异常的分歧 | 计划消费者、状态交接或执行约束。映射错误未排除前，不急于换搜索。 |
| 合法计划稳定执行，但主目标仍差 | 损失集中在哪类列车、资源或决策；当前选择为何保持这些损失 | 初始顺序、目标计算、候选比较、瓶颈协调；没有 bug 也应进入质量研究。 |
| 失败列车或高损失列车共享交互 | 具体冲突/等待依赖、通道或时间约束，是否存在可行替代选择 | 改变排序、受影响集合或联合邻域，使当前独立修改无法表达的协调成为候选。 |
| 搜索未找到计划或频繁耗尽预算 | 合法转移、约束是否过强、拒绝原因、状态表示及实际展开 | 搜索表示与剪枝、约束粒度或资源分配；不能把未找到认成无解，也不只加时间。 |
| 候选反复访问，成熟计划难再改善 | 访问分布、邻域能改变哪些决策、最好解是否正确保存、退出原因 | 先修漏访/保存错误；无错误时考虑覆盖、邻域或搜索选择，不能只放宽接受。 |
| 静态计划良好，事件后执行退步 | 首次交接差异、阻挡来源、修复影响边界和新计划接纳依据 | 依赖执行、受影响部分修复与替换判据；依据事件选择范围，不能默认越大越好。 |
| 计算时间限制了质量 | 热点、重复构建及每份资源获得的有效搜索与质量变化 | 增量维护、复用、搜索分配或覆盖；用实际限时质量评价吞吐收益。 |
| 本地改善，真实评分退步 | 代码与结果关联、评测规则、逐例变化、超时及条件差异 | 先确定退步发生在哪层；原因未知时不直接诊断过拟合或宣称方向耗尽。 |

位置不动不直接等于浪费时间；慢车可能仍在单元内推进，等待也可能为满足约束所必需。等待环只是线索，需要核实外部参与者、可用转移与解除事件，不能直接称为死锁。

相关 [算法思想](algorithm-playbook.md) 用来说明“改变什么表示或决策，为什么可能影响当前损失”；[真实案例](reasoning-cases.md) 用来检查类似尝试的条件与失败方式。选择符合证据的方向，不按顺序安装算法，也不要求所有问题都归入现有案例。

## 4. 形成一个可检验的改进决定

把观察、解释、实现和实测结果分开：

- **观察**来自代码、状态或评价，例如某类实例中实际完成质量较弱。
- **解释**说明当前机制为何可能造成该损失，并指出什么证据会推翻它。
- **实现**对应使用者的具体文件/函数和要改变的决策，不只写算法名称。
- **实测结果**报告候选是否改善主目标、影响了什么约束与代价，以及证据范围。

缺少关键证据时补会改变选择的观测；不必先建立全量遥测。已有质量差距、合理机制和可比较的评估，就可以开展有界候选实现，不要求先证明存在软件 bug 或完整因果链。面向当前 benchmark 比较几种排序、邻域组合、接受策略或预算分配，本身就是有效研究；将理由标为假设，用实测筛选。组合候选可以先回答“整体是否更好”，只有拆分贡献会影响下一步时才做消融。

在实现前选择能体现机制收益及可能退步的真实评估案例。策略影响整局就评估足够长的真实执行，不能把固定动作回放或一个合成小例当作质量证明。评估方法见 [质量评估](quality-evaluation.md)。

## 5. 负结果更新方向，而不是自动结束

保留一个简短的方向表，避免无依据重复：

| 主要剩余损失 | 已试机制及证据 | 尚可考虑的不同机制 | 下一项决定需要什么 |
| --- | --- | --- | --- |
| 当前用户证据 | 实现失败、机制无益、局部有益或已验证退步 | 从表示、顺序、邻域、执行/修复、吞吐等相关层选择 | 一个观测、实现或质量比较；缺条件则写具体缺项 |

例如，若单项修改确实无法改变相关列车的相互制约，应考虑能够同时改变那些决策的邻域；若邻域可表达但很少被访问，检查选择与预算；若有机会却被错误代理拒绝，检查目标判据。这些是由证据导向的层次切换，不是推荐的固定流水线。

拒绝一个候选后，重新查看仍未解释的主要损失。一次失败首先否定受测实现、设置和条件，不自动否定整个算法家族；若证据支持降低该方向优先级，就转向不同机制、组合或搜索覆盖。少数参数或修复尝试无益，不能推出“已经到顶”。目标未达且还能推进时继续研究；只有 [执行流程](autonomous-research.md) 中具体的停止或阻挡条件才结束或暂停整个任务。

## 6. 工具与结论边界

优先复用当前项目原生评测及复现入口。按需使用 [轨迹工具](tooling.md)：诊断首处分歧和显式等待、切片阅读、真实适配器回放、预约事件与实际快照核对。切片不是仿真；回放结果取决于状态与适配器是否充分；合成 runner 不代表 Flatland。

局部检查可以确认受测行为修复。优化结论还需要实际候选求解器的质量比较与对应晋级证据。按 [实验记录](experiment-card.md) 保存目标差距、机制、实测变化、最好版本和下一步，不把诊断成功等同于分数提高。
