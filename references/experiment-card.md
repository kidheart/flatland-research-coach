# 实验记录：目标、机制与实测质量

**简体中文** | [English](en/experiment-card.md)

复用使用者已有记录系统。默认用简短记录保存决定，只有复杂机制或难以解释的结果才展开；不要求每轮写报告。自动模式由 agent 记录自己的判断，交互模式可让使用者先表达，不冒充使用者观点。

## 默认短记录

~~~text
接手与目标：<当前/最好版本和成绩、评分细则位置；默认满分或用户指定目标；缺失信息和询问状态>
方案与差距：<现有能力、主要损失；架构升级或针对性强化的理由；最好已验证值及证据层>
机制与改动：<观察和解释分开；用户文件/函数、候选版本；预期改变哪个决策>
检查与质量：<冒烟结果；实际候选 solver 的代表评估、基线与候选主指标、主要退步和资源>
晋级证据：<开发/筛选/独立验证/权威结果；实际完成、失败、缺失或超时；未证实部分>
去留与后续：<候选/各证据层最好版本的位置；接受或拒绝理由；下一机制或具体暂停条件>
~~~

主指标没有测到就写“未测”，不是零；没有权威结果就写“未获得”。不同证据层、评测条件或目标的数值不要放在一起相减。已有记录回答了字段就引用它，不复制整段原始输出。

**冒烟通过不能完成质量优化的接纳。** 实际比较与晋级条件见 [质量评估](quality-evaluation.md) 和 [执行流程](autonomous-research.md)。纯粹的限定修复可以记录“受测故障已修复，整体质量未评估”；当总任务仍有质量目标时，继续处理剩余差距。

## 实现前：明确为什么试、怎样选择

需要展开时，只补当前决定所需字段：

~~~text
相关目标、硬约束和实际评价规则：
基线与最好版本的位置、结果及可复用条件：
主要剩余损失；代码/轨迹/逐例结果中的依据：
当前解释或经验猜想；准备看什么结果决定去留：
准备改变的决策、关联改动或参数/组合选择；作用范围：
代表评估为什么覆盖预期收益与可能代价：
候选接纳标准；什么证据才能晋级到哪一层：
已知运行成本、实际资源限制与超时：
~~~

算法思想可查 [机制手册](algorithm-playbook.md)，相似经历可查 [真实案例](reasoning-cases.md)。两者帮助形成预测，不提供当前用户的结果。简单实现错误不必强行编造竞争假设；合法但低质量的求解器也不必先找出 bug 才能开展算法改进。

经验试错可直接记录“为何选这些有区别的候选、谁在相同条件下表现更好、下一轮如何缩小选择”。不要求先证明因果；组合获益尚未归因时，保留整个候选及事实，不强制追加全组合消融。后续只有在解释能改变决策时才进一步拆分。弱起点的必要关联升级可以一起验证，不用为满足“一次一个小改动”拆散。

## 运行后：保留可比较的事实

~~~text
实际代码/配置、输入、环境、入口及资源条件：
候选求解器是否实际参与规划/修复决策：
预期实例与实际完成实例；缺失、失败、超时：
主指标与关键约束；逐例改善和主要退步：
基线比较是否有效；资源代价与运行波动：
数据用于开发、筛选还是未参与选择的验证：
权威目标结果（未获得则注明）：
观察支持什么、不能证明什么；候选去留：
~~~

不得只保留成功或改善的实例。固定动作回放不自动证明新规划策略有效，计划估计也不自动代表实际执行质量。只有条件匹配的基线可以复用；否则补所需比较，不能借旧结果背书。

收益接近波动时，做能决定去留的有界比较或保留未确认候选，不扩大成无目的的矩阵。质量不升或权威结果下降时，先记录实测退步和未知原因；没有证据不能直接写“过拟合”。保留此前最好版本，不能以本地候选替换权威最好版本。

## 方向更新与阶段结束

用一小段记录**剩余损失 → 已试机制与结果 → 其他可行方向 → 下一项证据或缺少条件**。拒绝候选后更新解释、选择其他机制；不把一项失败写成整个任务结束。若暂停，依据 [停止规则](autonomous-research.md) 说明具体条件及恢复所需内容。

最终总结主目标是否得到相应证据确认、留下了什么可靠版本、哪些机制有效或失败以及适用边界。未达标就明确未达，不宣称普遍最优或保证一定成功。分享时只用获准材料；不需要公开原作者的源码、参数、提交标识或获胜组合。
