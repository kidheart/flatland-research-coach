# 使用者自己的实验记录卡

**简体中文** | [English](en/experiment-card.md)

当研究已形成可检验的假设时使用。已有实验记录系统就复用它，不要求新建额外表格。短实验可以只记录几行。自动模式由 agent 主动填写与更新；交互模式先让使用者表达，教练再补充。下文第一人称指当前提出判断的人或 agent，不能冒充使用者观点。

## 实验前：明确假设与对照

```text
我想解释的现象：
自己的环境与评测中，和这个问题相关的条件：
参考案例（若适用）；相似条件、不同条件与不适用的迹象：
基线与最好已验证版本的位置及证据：
我目前的解释：
另一个也能解释现象的原因：
这次要改变什么、固定什么：
如果两种解释分别成立，我预计看到什么：
哪些结果会让我放弃或修改当前解释：
候选的接受标准与不可退步的硬约束：
本轮及剩余总预算；停止条件：
```

交互模式只补影响结论的遗漏；自动模式由 agent 提出待检验假设和审查意见。两种模式都不能捏造数据、结果或使用者说过的话。若因果假设还不能导出可区分的预测，先缩小问题，暂不跑昂贵实验。事实核查或接口验证只需说明检查能回答什么，不必凑出另一个解释。

## 实验后：把事实和判断分开

```text
实际测试的代码/配置与数据标识：
预期样本与实际完成样本；失败/超时：
同一次运行中，新步骤前后的变化（如果适用）：
不同运行的完整结果与资源消耗：
关键约束与辅助指标的变化：
真实评测结果（尚未获得则写未获得）：
观察支持什么，不能证明什么：
结论依赖哪些前提；什么新证据会让我重新考虑：
接受、拒绝或待确认；保留的最好版本位置：
我的下一步选择及理由：
```

不要用局部检查代替完整执行，也不要把本地结果自动换算成服务器分数。收益接近波动时，选择能控制主要不确定性的配对或重复实验；自动模式在预算内自行选择并执行，交互模式引导使用者选择。没有新疑点就复用已有有效证据。

## 交互模式的简短反馈结构

“你观察到了……，这支持……；目前还不能排除……。你准备通过什么观察来区分它们？”

已经得到充分证据时，直接认可该结论的适用范围并推进，不制造无止境的反问。使用者要求直接解释时可给明确说明，再让其将判断应用回自己的问题。

## 结束一段研究时

总结方法为何可能有效、依赖哪些前提、在哪些环境还没有证据，以及如何识别失效。自动模式由 agent 根据记录交付总结；交互模式可请使用者先用自己的话说明。保存其自己的可复现版本与结果。达到的是当前定义的目标，不自动升级为所有 Flatland 任务上的通用最优解。

若要分享研究经历，只使用使用者明确允许分享的材料；以虚构例子解释方法即可，不需要来源项目的参数、源码、提交标识或获胜配置。
