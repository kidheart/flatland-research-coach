# 自动研究：让 agent 用实验推进优化

**简体中文** | [English](en/autonomous-research.md)

用于使用者自己的 Flatland 工程。这里的问答发生在研究与审查环节，使用者不必逐轮答题。先执行当前授权内能确定的工作，只把影响目标、成本或操作范围且无法从材料中推断的关键问题交给使用者。

## 确立本轮边界

从项目说明、代码、日志和当前请求中核实：工作目录与可修改部分；主要评价指标和硬约束；基线版本与已有证据；可用数据和真实执行入口；时间、计算、实验次数等资源预算。复用现有记录，不要求使用者重新填表。

预算覆盖所有 agent 和实验，共享预算不能因委派而扩大。为可能长跑的实验设置宿主能够执行的超时，预留分析和保存结果的时间。未给预算时，可先做只读核实并声明保守、有限的本地试验范围；无法估计成本的长跑需要先澄清，不能把“自动优化”当成无限计算授权。尚未获得的回答不构成许可。

在用户项目中保留可恢复的基线和最好版本；把候选与未验证改动分开。只撤销本轮自己引入的失败候选，不覆盖使用者已有修改。外部提交、推送、分享和收费资源依照当前会话授权处理，不因启用本模式额外要求重复确认，也不凭 skill 自行取得权限。

## 用真实案例选择调查方向

先从 [脱敏思考案例](reasoning-cases.md) 的索引选与当前现象相符的一项。记录：哪个条件相似、哪个条件不同、案例建议检查什么、什么结果会推翻借鉴它的理由。案例是生成对照实验的依据，不是把所有曾经有效的方向一起装进项目。

例如，候选只在弱初始解上显得有效时，先与当前成熟基线比较；内部总量和真实评价排序不一致时，先核查计分与逐例变化；怀疑实现提速时，将相同工作量对照与限时完整执行分开。这些分支来自具体经历，详见案例中的实际观察与结论边界。

## 按需要分工，不能用共识替代证据

| 职责 | 要交付的内容 |
| --- | --- |
| 研究与整合 | 确定当前问题、可检验假设、候选改动和实验合同；维护最好版本与剩余预算，决定下一步。 |
| 反证审查 | 检查可能的混淆因素、反例、约束退步和实验区分力；提出最值得补的检查，而不是要求无限加测。 |
| 实施与评测 | 实现候选，运行指定检查，返回实际版本、原始结果、失败与资源消耗。该职责可由整合 agent 承担。 |

存在真实委派工具且能节省时间或提高判断质量时，给另一 agent 一个独立、有限的任务。提供任务规则、必要代码或候选差异、原始结果和预期产物；独立评审尽量不先给“它应该有效”的结论。说明谁可以改哪些文件，由一个整合者接纳变化；独立候选使用隔离副本或不相交的修改范围。

没有多 agent 工具时，同一 agent 先提案再检查反例，明确标记为单 agent 自审。不要写虚构的“研究员说／审查员说”，也不要声称获得独立验证。审查应导向一个可执行检查或明确的接受/拒绝理由；只有新证据或新问题才需要继续争论。

避免让相互竞争硬件资源的基线和候选计时实验并发。文本审查和独立分析可以并行；实验条件和版本依赖需要保持明确。

## 自动迭代循环

1. **锚定基线。** 读取已有可核实结果；需要复现时运行相关小检查或基线，记录代码、数据、环境、种子和命令。不要把最新文件自动当作最好版本。
2. **形成候选假设。** 围绕一个明确的问题描述观察、可能机制、竞争解释、改动与固定项。说明预期结果和反证条件；若只是定位接口事实，写明检查能回答什么即可。
3. **审查实验。** 让审查者或自身检查比较是否公平、指标是否对应目标、失败是否计入。把最有影响的问题落实进实验；不为形式凑多个 agent 或对照。
4. **实施并运行。** 做能检验假设的最小合理改动。先运行必要的正确性检查，再在预算内进行资源可比的任务执行。每次记录实际完成情况；失败、超时和没有改善都属于结果。
5. **决定去留。** 只有满足硬约束且达到事先确定的接受标准，才把候选提升为最好已验证版本。结果接近波动或验证不充分时，保留为待确认候选；不让最好版本指针悄悄指向它。拒绝后恢复本轮改动，保留失败记录。
6. **据证据继续。** 更新假设、案例适用条件与剩余预算。有新的可区分问题且预算足够就继续；不要因为一次正收益就结束持续优化请求，也不要重复没有新信息的参数扫描。

复用 [实验记录卡](experiment-card.md) 的字段。自动模式由 agent 填写自己的假设、审查意见与判断；这不等于捏造使用者观点。记录可以简短，但须区分提议、实现、启动、完成和已验证。

## 比较与停止

固定输入、版本和相关随机性，并说明采用固定工作量还是相同时间预算。对因果解释，区分策略变化、吞吐变化和机器波动；对目标改进，记录完整执行中的目标指标与硬约束。候选筛选数据与未参与调参的验证数据应分开；已经反复用来选择候选的数据不能继续叫“未见验证集”。

当目标得到相应证据确认、预算耗尽、没有新的可检验方向，或遇到关键输入/工具/权限缺失时，保存状态并停止相应工作。缺少执行工具时只能提供分析与可交接的实验合同，明确标记“未运行”，不能声称已完成自动优化。宿主结束执行后，不宣称还在后台运行；需要持续运行能力时由宿主提供。

交付最好版本及可恢复位置、与基线的实际比较、候选去留记录、耗时和失败、仍未知的部分及停止原因。只有本地证据就报告本地结论，不转换成比赛分数或全局最优性。优化失败也应交付有依据的方向排除和保留的可靠基线。
