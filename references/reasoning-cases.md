# 真实脱敏案例：从观察到修改决策

**简体中文** | [English](en/reasoning-cases.md)

这些案例来自同一次 Flatland 研究，经创建者授权回查实验笔记、结构化结果及历史评测表后改写。它们包括未保留的方向和有条件的正面结果，顺序不代表最终架构或推荐组合。尝试理由是依据当时改动与上下文重述的假设，不是逐字引语。

本文不提供源码、精确参数、版本标识、逐例成绩或原始日志，是有来源依据的定性案例报告，不是可独立复现的公开性能比较。每卡把真实经历及证据边界与当前决策规则分开；规则不是对原经历补写的事实。

## 先诊断，再按需选卡

以 [诊断与修改决策](diagnosis.md) 为主入口。先用当前项目证据判断问题，再借鉴相似案例；六例不保证覆盖你的环境。索引中的假设都待核实，不能由现象直接认定原因。

| 当前观察 | 待核实的诊断假设 | 决策卡 |
| --- | --- | --- |
| 改善停滞，放宽接受后活动增多 | 最好解丢失、重复访问，或当前接受规则没有收益 | C1 |
| 弱起点有效，完整系统中收益很小 | 起点不可比、阶段重复，或剩余联合约束未被处理 | C2 |
| 预约维护耗时显著 | 重复构建是瓶颈，且可安全复用未变状态 | C3 |
| 完成量和总代价改善，实际评分下降 | 结果对应错误、代理目标错位，或逐例退步被汇总掩盖 | C4 |
| 更广修复的计划估计更好，执行退步 | 交接状态不一致、替换判据失配，或范围变化有副作用 | C5 |
| 同一批候选反复优先，后续候选少有访问 | 遍历遗漏、预算截断，或覆盖策略不适合当前候选集 | C6 |

每卡的“修改位置”只指概念职责。agent 应从**当前用户源码**定位对应函数和调用链，不寻找或移植原作者实现。先检查已有记录，再做一个能区分关键分支的局部冒烟；有证据就实施相应修改，不把诊断停在实验安排上。记录可用 [实验卡](experiment-card.md)，加测遵循 [自动研究流程](autonomous-research.md)：只有局部结果不足以决定接纳、且额外检查会改变决定时，才扩大验证，不默认运行大量 A/B。

## C1：放宽接受规则，探索发生了，结果却没有更好

**真实经历。** 改善变少后，尝试允许等成本横移，以及按历史成本接受部分暂时退步。理由是严格改善可能挡住更好区域。固定工作量筛选中，等成本版本最终成本持平而耗时增加；历史成本版本确有横移、上坡接受和最好解更新，但最终返回的最好结果仍弱于对照。当时未集成这些候选，保留已验证的严格改善流程。

**证据边界。** 实验笔记和结构化对照支持上述观察，不能确定原因是接受规则、邻域、预算还是实例结构，也未否定其他允许暂时退步的方法。

**触发→先核实。** 当前搜索停滞或接受次数激增时，查看实际访问的不同状态、接受类型、最好解轨迹和最终返回值；先区分“未找到更好解”和“找到却没保留”。

**证据→修改位置与行动。**

- 更好解已发现却未返回：修复最好解保存、恢复或返回路径，暂不调宽接受规则。
- 访问反复落在相同状态：检查候选生成、去重与邻域选择；证实哪处造成重复后局部修改，不能仅凭停滞认定接受过严。
- 确实探索新状态但最好结果无益：保留当前已验证版本，停用这个候选；接受次数增加不足以继续投入。

**最小检查与停/启。** 从一个相关保存状态短跑，核对访问与最好解记录及返回值。修复已覆盖已知错误即可结束该轮；若是否保留候选仍取决于收益，再补相关的可比资源检查。仅在平台结构、多样性不足或预算/实例变化提供新依据时重启，不能只因为“再调一下也许有效”。

## C2：小组联合搜索有用，却不一定值得追加到成熟基线

**真实经历。** 对少量相互影响的列车联合搜索等待和绕行，之后也尝试更宽及关联的组，希望处理逐步调整难以协调的决策。小图结果与独立联合最短路对照一致；弱初始计划上多数筛选案例改善，充分优化的成熟基线后，直接可比案例只剩个别微小收益，其余持平。当时保留研究候选，用保存的成熟完整计划检查更宽或关联的组，避免反复重跑昂贵基线；后续筛选仍主要是小收益，未据此增加提交复杂度。

**证据边界。** 小图对照、筛选结果及笔记支持这些差异。小图一致不证明大型实例最优；“成熟基线已处理相关结构”仍是未证实的解释。

**触发→先核实。** 新阶段在完整系统里收益小，先核实起始计划、资源条件及阶段是否实际执行，再看失败轨迹是否还包含它能处理的联合约束。

**证据→修改位置与行动。**

- 起点不同或阶段未运行：先修正保存计划的载入、阶段接入或结果记录，暂不扩大联合搜索。
- 只对弱起点有效：不要追加到成熟流程末尾；若早期工作确是瓶颈，再在阶段调度处评估替换早期工作。
- 可复现的剩余交互没有进入当前组或边界：定位分组选择与联合搜索边界，针对该交互修改；若没有这类证据且边际收益不足，保留当前版本。

**最小检查与停/启。** 用同一份相关保存计划，检查阶段调用及一个剩余交互的局部结果；只有决定取决于新增价值时，才比较基线延续与候选的资源和收益。无足够边际价值就停止追加；基线改变、早期收敛成为瓶颈，或新轨迹暴露未处理联合约束时再开。

## C3：增量预约维护，行为一致后才有提速的意义

**真实经历。** 为减少局部搜索反复构建预约的工作，尝试只撤销和重建受影响路径，复用其余信息；难点包括共享占用、撤销恢复和异常中断。表级对照及异常回滚检查通过；固定轮数优化器对照中，完整路径、成本、随机状态和接受历史一致，候选耗时更低。当时保留候选，再做不同规模的完整执行回归，分别核对实现效率和执行收益。

**证据边界。** 有结构化预约状态及优化器行为对照，但候选含其他相关效率改动，不能把全部优化器提速归给单项改动；表级计时归因较窄。有限一致不是形式化等价证明，也不保证整局更快。

**触发→先核实。** 维护数据疑似占时，先看剖析或局部计时，确认重复构建是否真是主要开销，再核实更新、共享占用与恢复的语义。

**证据→修改位置与行动。**

- 开销主要在别处：转向实际热点，不增加增量维护复杂度。
- 撤销、拒绝或异常后状态不同：先修复预约归属、更新及回滚路径，暂停速度结论。
- 重复开销显著且状态语义明确：在预约构建/更新边界做局部复用，维持受测行为；不要同时换搜索策略来解释提速。

**最小检查与停/启。** 对修改涉及的正常更新、重叠占用、拒绝和异常恢复做局部差分；通过后用小规模固定工作量核对行为与耗时。状态有差异就停下定位；开销不值得或维护成本抵消收益就结束此方向。只有整局资源/质量决定仍未解决才扩大运行。限时结果因多做工作而改善，应记为效率收益；热点或状态模型改变时重新检查。

## C4：完成更多、总代价更低，实际评分仍下降

**真实经历。** 增加搜索投入并调整任务紧迫性的考虑，期待困难场景中完成更多、按时到达更多、总代价更低，从而改善表现。两份历史实际评测表却显示这些汇总量改善而最终评分下降，逐例表中有明显退步；分歧也存在于同类实际结果的不同汇总层次。当时转向逐例退步和失败状态，提出针对性修复候选继续验证，不再仅凭汇总改善决定提交。

**证据边界。** 用户提供的两份原始评测表和逐例记录可支持观察，比口头测量摘要直接；它们没有给出具体计分公式，也未证明某种故障是唯一原因。

**触发→先核实。** 代理量与实际目标冲突时，先对应代码、数据、评测条件和逐例主指标；可访问评测器就核实聚合/归一化规则，不可查的规则保留未知。

**证据→修改位置与行动。**

- 版本、实例或指标对应有误：修正结果关联及评测记录，暂不改规划器。
- 当前选择判据优化了错误目标：依据已核实规则修正目标计算/候选选择；规则未知时用实际返回指标，不臆造公式。
- 对应无误，退步集中在具体失败：从相关轨迹定位造成退步的约束处理或执行路径，修该原因；不要继续只加搜索投入来追求汇总改善。

**最小检查与停/启。** 先重核现有表中相关行及汇总；必要时仅回放一个能解释退步的实例。评价对应或局部故障修复后停止该轮，接纳条件仍不明才扩大验证。若实际目标确是该汇总量且执行/计分一致，就可直接用它选版本；此例反对未经验证的指标替代，不排斥汇总指标。

## C5：扩大修复范围再按估计择优，也可能执行退步

**真实经历。** 故障修复后，额外生成覆盖更多活跃任务的重排方案，按计划质量估计与已有方案比较，希望解除局部修复留下的阻塞。历史记录保留测试、收紧替换条件、再测、关闭和删除逻辑的过程；当时测量摘要报告某个本地场景的执行惩罚及规划时间增加。随后撤掉扩大替换范围的比较机制，恢复受保护的既有行为，再评估其他候选。

**证据边界。** 依据是测试调用、编辑/回退记录和当时助手的测量摘要，没有保留可独立核对的原始运行输出。同期还改过其他修复行为，不能唯一归因于该机制；“震荡”或“修复范围必须匹配故障范围”只是可能解释。

**触发→先核实。** 计划估计改善而执行退步时，查替换时刻、前后预计代价、实际状态及首次轨迹分歧，把范围、接受规则和同期改动分开。

**证据→修改位置与行动。**

- 新计划与执行时状态或约束不一致：先修复计划提交、状态交接或执行校验处，暂不扩大重排。
- 交接正确，但“估计更好”的替换伤害主目标：修正方案比较/替换判据；原因未清时恢复已验证行为，不用估计覆盖已验证结果。
- 局部修复确实留下可复现的协调缺口：在受影响任务选择与修复边界处做针对性修改，再检查执行；不能仅凭等待或计划估计断言扩大范围有效。

**最小检查与停/启。** 回放一个相关替换事件到首次分歧，修复后覆盖该事件及受影响的执行片段。硬约束失败或主目标退步就停止升级候选；接纳还依赖整局效果时才扩大验证。执行器条件改变，或出现能受控验证的局部协调失败时重启，不把本例当成永久禁止广域修复。

## C6：后面的候选得到访问，收益有限，时间也增加

**真实经历。** 改变局部细化起点遍历，让较后候选也有机会被检查，避免预算反复花在少数优先项。行为检查记录了有改善及无改善时的遍历；保存成熟计划上的筛选多数改善、其余持平；配对完整执行中总体成本略降，完成及按时到达数未退步，总耗时增加，并保留新增阶段前后的变化。当时完成本地筛选和完整执行验证；所引材料未给出随后实际服务器表现，不把后续成功反向归因于此。

**证据边界。** 行为检查、保存计划筛选及完整执行记录支持有限收益和时间代价，但未完全分离额外预算与覆盖策略的因果贡献。不能据此认定旧版损失由覆盖不足造成；同次阶段收益、跨次初始计划差值和最终执行差值不能混写。

**触发→先核实。** 候选访问疑似偏向前部，查看实际访问分布、退出原因和耗时，区分遍历缺陷与预算内的有意取舍，不只数迭代次数。

**证据→修改位置与行动。**

- 存在非预期提前退出、游标复位或漏访：修复候选遍历/终止处，先维持现有预算。
- 遍历无误，但轨迹显示未访问区域有相关机会：在候选顺序或预算分配处小改，检查是否在现有资源内产生收益。
- 覆盖已足够，或收益仅靠更多时间：不把覆盖认作原因；资源上限不允许就停止该候选，允许时如实记录资源换质量。

**最小检查与停/启。** 从一个相关保存状态检查有/无改善时的访问及退出路径。若修复后选择已明确就停止；只有覆盖与额外预算的区别会影响接纳时，才补等预算遍历比较或单独的预算对照。候选集、预算或热点改变时重查。

## 决策落地

每轮记录“当前证据→判断→定位的用户源码职责/函数→修改或保持→最小检查→结果”。证据不足时做能区分原因的检查；证据足够时直接修复对应位置。不匹配就提出新假设，不强套六例，也不把当前条件下的失败推广为算法家族禁令。

目标达成后保留成功版本、失败尝试和未知事项，不需要穷尽替代路线；成功也不证明每个模块都必要。新增案例须有真实依据或标明虚构，保留实际行动与建议的区别，并检查组合泄露风险。交互模式可讨论一个关键判断，自动模式由 agent 完成诊断、修改和验证。
