# 算法机制：从损失选择能改变结果的决策

**简体中文** | [English](en/algorithm-playbook.md)

这是按当前方案与失分选用的机制库，结合经授权复核的研究材料与通用算法思想。它不列出原方案的最终组合、顺序、参数或实现；这些机制无需全部采用，出现于成功版本也不证明其独立贡献。算法家族并不多，关键在于把它们组合成适合当前 benchmark 的求解器，再用实际成绩改进组合。

## 先判断现有方案需要跨多大一步

先检查当前源码、最好已验证版本与评测入口，读取当前成绩、逐项失分及评分规则；缺少的评分信息直接询问，已有材料不重复问。用户没有另定目标时，默认追求当前 benchmark 的 **100% / 满分**，不询问是否要满分，也不把所有列车到达自动等同于满分。入口细节见 [诊断](diagnosis.md)。

| 当前能力与成绩证据 | 首个候选的改动幅度 |
| --- | --- |
| 独立最短路或固定顺序规划，主要损失来自冲突与资源争用 | 直接补齐时空约束和多列车协调能力；可将低层规划、预约与顺序选择作为一个完整候选，不逐轮只调启发式常数 |
| 已有合法优先规划，后规划者持续受阻，缺少联合改变能力 | 评估多起点顺序或关联邻域重排，优先解锁当前骨架表达不了的决策 |
| 已有成熟的规划与改进阶段，剩余分数集中在少数场景 | 保留有效骨架，研究邻域、路线与时序多样性、执行协调或预算分配；必要时替换瓶颈阶段 |
| 简单方案已接近目标，损失集中在实现错误或计分错位 | 先处理实际失分处；算法名称简单不是强行换架构的理由 |

这是按能力选择改动幅度，不是按名称评定优劣。一个有统一目的的候选可以包含互相依赖的多个改动。缺少精确评分时，先完成代码能力判断和低成本诊断；把待确认的取舍写清，不凭空宣称已有质量提升。

| 当前损失信号 | 优先研究的决策 |
| --- | --- |
| 指标变好，真实评分却没有改善 | 目标、可行性与代理评价是否混在一起 |
| 路径合法性错误，或时间搜索耗尽预算 | 状态表达、启发式与时间压缩 |
| 后规划列车总是绕路或错过通行机会 | 谁先占用有限通行资源 |
| 单列车反复重算仍无改善 | 哪些相互制约的路径必须一起释放 |
| 计划可行，故障后执行代价激增 | 通行依赖、实际进度与修复范围 |
| 大量时间用于重建未变数据 | 状态维护的成本能否转成更多有效搜索 |
| 总有改善，但只访问同一批候选 | 预算内的覆盖与继续搜索位置 |
| 预测很准时有效，换环境后失效 | 决策依赖的信息是否实际可得 |

所有下述小故事均为**合成教学例子**，不是原始地图或成绩。算法候选经过正确性检查后，还要接受 [质量评估](quality-evaluation.md)：有代表性的真实完整执行与已验证版本比较，才能讨论质量提升。一次冒烟只回答局部机制是否按预期工作。各项预期是试验要观察的结果，不要求 agent 在尝试前证明原因。

## 目标错位：先改变“选择哪个结果”

- **信号 → 决策：** 提前到达数、搜索内成本或平均路径长度改善，最终评分下降。先展开当前评测的逐例计分与汇总规则，重新确定候选和最好版本的选择依据。
- **机制：** 区分硬约束、正式目标、预测代价和搜索启发式。代理值可以帮助生成候选，却不能冒充正式得分；完成率和代价的优先级应来自用户目标或评测规则，不能默认采用字典序。
- **当前代码职责：** 定位计分解析、候选接受、最好版本保存和最终返回。搜索当前状态与已验证最好版本分开；允许探索暂时退步也不能丢失最好版本。
- **合成例子：** 修改让更多列车按时到达，却使另一组列车多绕很远。若正式目标累计行驶与迟到代价，按时到达数增加本身不能决定升级。
- **可证伪预测 → 评估：** 同一组真实完整执行中，新的选择规则应改善正式目标且满足约束；同时保留逐例退步与资源开销。若仅代理值提高，拒绝“已优化”的结论并继续定位错位。

真实反例见 [C4：指标改善而评分下降](reasoning-cases.md)；[C1](reasoning-cases.md) 提醒，更多接受与更频繁的最好解更新也不等于最终更好。

## 状态与时间：A*、方向信息和安全区间

- **信号 → 决策：** 同一格被错误地视为同一状态，或长等待造成大量时间展开。检查后续可行动作是否还取决于方向、时间、速度阶段与占用状态，再选择搜索表达。
- **机制：** 朝向影响铁路转向时，应进入状态；逆向静态距离可给搜索提供比纯几何距离更有信息的下界。若动态约束允许把连续安全时刻合并，可考虑安全区间搜索；到达标签和等待可行性仍须符合当前模型。[SIPP 原论文](https://publications.ri.cmu.edu/sipp-safe-interval-path-planning-for-dynamic-environments)
- **当前代码职责：** 定位状态键、合法后继、启发式缓存、预约冲突检查及稠密路径还原。不要只更换优先队列而保留错误的状态合并；版本或速度语义变化时重新检查假设。
- **合成例子：** 两列车从不同方向进入同一岔道，可用出口不同；仅按位置去重会丢掉可行路线。另一条线的长等待可以由一个安全区间表达，而无需枚举每次原地等待。
- **可证伪预测 → 评估：** 表达修正应消除对应非法路径或漏解；压缩应在相同约束下保持路径质量，并在固定时间预算的真实场景中改善完成情况或代价。若仅减少扩展数、最终质量不变，报告为效率结果。

## 优先规划：把顺序看成资源分配

- **信号 → 决策：** 单列车路线都合理，后规划者却持续绕远或等待。调查已固定路径占据的岔口和单线区段，决定谁应先获得这些通行机会。
- **机制：** 优先规划逐个规划并预约；其速度来自固定前面决策，也因此难以让早规划者主动让路。截止期紧张度、剩余距离与资源依赖提供不同排序依据，不能把任何一种当成普遍最优。
- **当前代码职责：** 定位初始顺序生成、路径预约、缺失路径处理和候选保存。用少量不同排序依据或有界随机扰动生成多个起点，再按当前目标保留候选；也可只改变争用处的优先关系。多起点的价值是寻找不同资源分配，不能只靠增加随机种子数量判断进展。
- **合成例子：** 列车 A 先占住唯一通过区段，列车 B 被迫长绕路；A 若稍后通过，两者都能走较短路线。需要改变的是占用次序，不是给 B 的单体搜索增加深度。
- **可证伪预测 → 评估：** 受影响列车的争用代价应下降，代价不能只转移给未观察列车。在同一真实完整场景与固定资源下比较整体正式目标，再检查不同拥挤程度的代表场景是否保留收益。

## 关联邻域：LNS 要释放真正相互制约的决策

- **信号 → 决策：** 高损失列车重算多次仍返回同一路径，或一个新阶段只对弱起点有效。找出阻止其更好路线的已预约路径，再决定哪些路径需要一起撤出重排。
- **机制：** 大邻域搜索保留大部分解，对选中部分执行拆除与修复；Flatland/MAPF 中可用延迟、实际阻挡关系和多样性选择邻域。关联组负责处理已知依赖，随机或较宽的组可探索当前关联规则没覆盖的组合；重新插入次序也是搜索变量。扩大邻域能暴露联合改变，也会增加修复失败与时间成本。[MAPF-LNS 原论文](https://www.ijcai.org/proceedings/2021/568)
- **当前代码职责：** 定位损失排序、阻挡者来源、邻域扩展、重新插入次序与接受规则。区分搜索实际遇到的阻挡与仅共享位置的潜在关联；保留非选中路径，并能完整回滚失败候选。
- **合成例子：** A 的便宜路线被 B 预约，B 的替代路线又被 C 预约。只释放 A 不会改变答案；按依赖把相关决策纳入同一个候选，才可能发现三者共同获益的安排。
- **可证伪预测 → 评估：** 从当前成熟计划出发，候选应解除已记录的阻挡并改善完整执行目标。使用同一份保存计划做便宜筛选后，仍需验证实际运行；只赢弱起点不支持追加到成熟系统末尾。

真实的阶段收益差异见 [C2](reasoning-cases.md)；[C1](reasoning-cases.md) 中放宽接受规则未胜出，说明“换了搜索行为”仍需质量证据，不构成算法家族禁令。

## 多样性：分别改变空间路线与通行时序

- **信号 → 决策：** 搜索反复返回同样安排，但可替代岔路或通行顺序很少被尝试。区分是空间路线被固定，还是相同路线上的进入时间与先后关系被固定。
- **机制：** 不同的等长或近似长度路线可能产生不同争用；空间路线不变，交换进入次序或等待位置也可能改变整体结果。为两类候选保留机会，可以突破只缩短单车路径的限制。
- **当前代码职责：** 定位低层搜索的平局选择、替代路线生成、资源排队关系及时间安排。按需要生成空间候选、时序候选或关联组候选，不要求每次同时改变全部维度。
- **合成例子：** A 有两条同长路线，其中一条占用 B 的必经岔口；换另一条不缩短 A，却释放了 B。另一场景没有岔路可换，但让急迫的 B 先通过，仍可能降低整体代价。
- **预期观察 → 评估：** 查看候选是否实际改变相关争用，再比较完整执行的正式目标。同长不意味着等价，路线不同也不意味着更好；让实测决定保留哪些多样性来源。

## 执行协调：通行先后与实际进度必须一致

- **信号 → 决策：** 规划结果看似良好，一次故障却触发等待连锁或反复大范围改道。查清是通行时间变了、资源先后关系不合适，还是空间路线本身需要改变。
- **机制：** 类似 MCP 的协调可保留资源通行先后，依据实际进度重新安排时间；局部重规划则可改变有关路线。二者解决的约束不同。公开 Flatland 研究讨论了规划与执行协调的结合。[Flatland 规划与协调论文](https://ojs.aaai.org/index.php/SOCS/article/view/18576)
- **当前代码职责：** 定位动作提交、实际进度同步、资源进入令牌或依赖表、故障占用与修复边界。只在真实移动完成后推进对应状态；候选未被选中时，其内部重试状态不应污染当前执行。
- **合成例子：** A 故障停在区段内，B 等它腾空，C 又等 B。单纯把 A 的时间向后平移可能不够；先传播真实占用影响，只有固定先后仍不能解决时才评估改变相关路线或顺序。
- **可证伪预测 → 评估：** 新协调应降低真实故障场景的执行损失，且不新增碰撞、滞留或过多修复开销。先回放交接事件，再运行完整故障场景；重排后的纸面代价较低不能直接升级。

扩大修复曾执行退步的证据及其限制见 [C5](reasoning-cases.md)。等待图有环也不自动证明死锁，要检查释放条件与当前执行语义。

## 计算效率：把节省的时间转成质量

- **信号 → 决策：** 搜索预算大量消耗在重复构建未变预约或索引。先定位真实热点，再决定可复用的状态边界。
- **机制：** 增量维护保留未变路径，只撤销和加入受影响部分；引用计数处理共享占用，事务式恢复处理失败和中断。收益来自减少相同工作的重复，不能以损坏预约换取速度。
- **当前代码职责：** 定位预约增删、位置与时间索引、共享占用计数、缓存失效及异常回滚。要单独归因提速时保持搜索语义一致；也可把维护与搜索策略作为配套候选整体评估，但分别说明修改，不把整体收益归给单个模块。
- **合成例子：** 改动少量路径却每次扫描整个车队重建表，导致很多有价值的候选来不及尝试；复用未变预约后，同一时间预算能完成更多相关修复。
- **可证伪预测 → 评估：** 固定工作量核对行为与成本一致、耗时下降；再做固定总预算的代表性完整执行，检查更多有效候选是否改善正式质量。二者回答不同问题，不必对每个小改动都重复运行两套大评测。

正面经验与归因边界见 [C3](reasoning-cases.md)。如果质量未提高，保留真实的速度结果，并重新分配省下的预算，而不是宣称分数已经改善。

## 公平覆盖：停止重启同一个热点

- **信号 → 决策：** 搜索一直有小改善，但较后依赖组很少被访问。记录访问到的根、不同组、接受后游标位置和退出原因，判断预算是否被反复重启的前部候选占用。
- **机制：** 一次接受可以刷新阻挡关系，却不必清空本轮尚未访问的候选。保留待访队列与已访集合，给遗漏区域机会；完成一轮后再按新解重排，仍遵守总体预算。
- **当前代码职责：** 定位根候选排序、循环中的提前退出、接受后重启、依赖缓存和底层搜索截止时间。公平表示有依据地改善覆盖，不要求均分时间，也不要求穷尽所有组。
- **合成例子：** 组 P 每次省下一点，触发从列表开头重新搜索；有明显阻挡缺口的组 Q 始终排不到。保留 Q 的待访位置，才可能在现有预算内发现不同改善。
- **可证伪预测 → 评估：** 访问记录应显示此前遗漏的相关组获得机会；相同总预算的真实完整场景应改善正式目标或其稳定性。若收益只来自额外时间，应明确是资源换质量，不能归因为覆盖策略。

这个思路来自 [C6](reasoning-cases.md) 的真实继续搜索经验；历史收益与额外时间未完全分离，不能说它单独造成最终成功。计数增加也不等于收益。

## 预算分配：把有限时间投向仍能改变结果的搜索

- **信号 → 决策：** 初始规划耗尽时间、改进阶段反复做低收益工作，或在线修复挤占整局预算。检查各阶段的实际调用、候选数量、有效改进与截止退出，再决定时间花在哪里。
- **机制：** 起点多样性、邻域改进、尾部覆盖和故障修复会竞争时间。将省下的维护成本用于更多有希望的候选，或在不同规模与拥挤条件下调整分配，是算法设计的一部分；不是每个阶段都应增加预算。
- **当前代码职责：** 定位阶段调度、总体与局部截止时间、提前退出、已保存解的继续优化入口。比较小范围的分配或组合变化，保留可随时返回的最好解，并检查低层调用是否遵守时间上限。
- **合成例子：** 多个起点都产生相似争用，而对一个已知阻挡组的重排常有收益。减少重复起点，把时间留给重排值得试；另一种稀疏场景可能相反。
- **预期观察 → 评估：** 在相同总体资源下测量完整结果，记录预算耗在哪里。若增加总时间才变好，明确报告资源换质量；有实际收益且符合当前评测限制时，这仍是有效候选。

## 针对 benchmark 试错：先有方向，再让结果校正判断

有依据的参数、排序、邻域大小、接受策略和算法组合试验都属于正常优化。依据可以是当前实现缺少能力、某类失分、相似案例，或一个尚未验证但可解释的直觉；不必先完成严格归因分析。先挑少量差异有意义的候选，在代表性场景快速比较实际质量，再把资源投向有希望的区域。避免无差别参数网格与每轮全量评测，也不要把节省试验变成拒绝试验。

组合可能存在相互作用：一个阶段在当前组合中无益，不代表换起点、邻域或预算后也无益。可以将必要的配套改动一起作为候选，说明想解锁什么能力；只有需要解释贡献或定位退步时，再做针对性的拆分。针对用户这一个 benchmark 调整策略是有效目标，成绩声明保持相同适用范围即可，不必先证明跨 benchmark 通用。

连续几次失败说明这些候选在这些条件下没胜出。保留最好结果，检查尚未覆盖的路线、时序、联合范围和资源分配，再决定下一步；不能从有限试验推出“已经到顶”。重复尝试应带来不同参数区域、组合、信息或评测覆盖，不机械重跑同一个失败候选。

## 信息边界：预测条件也是算法的一部分

- **信号 → 决策：** 同一机制在新环境突然退步，或收益依赖某种“已知”的未来事件。核对正式接口、可观测状态和环境假设，决定哪些信息有资格进入约束。
- **机制：** 当前可见故障、明确提供的计划日历和不确定预测属于不同信息类别。预测吻合过一次不等于未来已知；模型失配时应撤销不成立的假设并保留可执行的应对路径。
- **当前代码职责：** 定位输入来源、时间对齐、模型状态、失配处理和候选选择。仅使用任务允许获得的输入，不依赖评测器内部状态；把版本、运动语义和预测误差列入适用条件。
- **合成例子：** 某模型按常见故障持续时间预留空档，实际故障提前结束后仍让列车等待。应检验观察更新是否释放过时约束，并将预测代价与已发生损失分开。
- **可证伪预测 → 评估：** 在假设成立与合理失配的真实代表场景中，分别检查正式质量、约束和应对行为。若只在强假设下有效，缩小适用范围；不要把有限基准成绩写成跨环境能力。

## 将一项机制变成下一次行动

写清“现有能力与成绩 → 想减少的损失 → 候选改动与预期 → 实际质量反馈 → 下一步”。证据不足时标明假设，执行能获得信息的合理试验。按 [质量评估](quality-evaluation.md) 保留实际目标最好的已验证版本，遵守其最小化或最大化方向，解释候选退步落在哪些场景。一个方向失败后，回到剩余损失与尚未检验的机制；局部无收益不等于用户目标已经完成。
